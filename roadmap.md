# EEL (eBPF Language) Development Roadmap

## Phase 1: Lexical Analysis (Current)
The foundation of the compiler, responsible for converting raw source code into a stream of meaningful tokens.

- [x] Define core token types (Keywords, Literals, Operators, Delimiters).
- [x] Basic Lexer implementation in C.
- [x] Support for all planned keywords:
    - [x] `probe`, `if`, `elif`, `else`, `repeat`.
    - [x] `map`, `int`, `string` (Type declarations).
- [x] Literal parsing (Strings, Numbers).
- [x] Arithmetic and Comparison operators.
- [x] Error handling for illegal characters and malformed tokens.
- [ ] Unit tests for the Lexer.

## Phase 2: Syntax Analysis (Parser)
Converting the token stream into an Abstract Syntax Tree (AST) that represents the program structure.

- [ ] Design AST node structures for:
    - [ ] Probe definitions.
    - [x] Variable declarations and assignments.
    - [ ] Function/Helper calls (e.g., `print`).
    - [ ] Control flow (If/Else, Loops).
    - [ ] Expressions (Arithmetic, Comparison).
- [ ] Implement a Recursive Descent or Pratt Parser.
- [ ] Parser error reporting with line/column information.
- [ ] AST visualization tools (e.g., Graphviz export).

## Phase 3: Semantic Analysis & IR Generation
Validating the AST and lowering it to a "Verifier-safe" Intermediate Representation.

- [ ] Symbol table management (Scope handling).
- [ ] Type checking (e.g., ensuring map keys/values match).
- [ ] eBPF Verifier pre-checks (Loop bounds, stack size limits).
- [ ] Implementation of a custom IR optimized for eBPF instruction mapping.

## Phase 4: eBPF Bytecode Generation
The "heart" of the standalone compiler—generating 64-bit eBPF instructions directly.

- [ ] Map EEL IR to eBPF instructions (ALU, Jump, Load/Store).
- [ ] Implement Register Allocation for the limited eBPF register set (R0-R10).
- [ ] ELF Object file generation (creating `.BTF`, `.maps`, and text sections).
- [ ] Support for eBPF Helper function calls (mapping EEL functions to helper IDs).
- [ ] Map definitions and relocations.

## Phase 5: Kernel Integration & Loader
Loading the generated bytecode into the Linux kernel and attaching to probes.

- [ ] Implement a minimal `bpf()` syscall wrapper.
- [ ] Program loading logic (mapping sections, setting up maps).
- [ ] Attachment logic for `kprobes`.
- [ ] Trace logging output handler (reading from `trace_pipe` or ring buffers).

## Phase 6: Expansion & Optimization
Future-proofing and expanding EEL's capabilities.

- [ ] **Targets:**
    - [ ] Tracepoints support.
    - [ ] XDP (Express Data Path) support.
    - [ ] Perf events.
- [ ] **Optimizations:**
    - [ ] Verifier-aware dead code elimination.
    - [ ] Instruction minimization.
- [ ] **Tooling:**
    - [ ] User-space CLI for loading/unloading programs.
    - [ ] Language Server Protocol (LSP) support for IDEs.
