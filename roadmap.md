# EEL (eBPF Language) Development Roadmap

## Phase 1: Lexical Analysis
The foundation of the compiler, responsible for converting raw source code into a stream of meaningful tokens.

- [x] Define core token types (Keywords, Literals, Operators, Delimiters).
- [x] Basic Lexer implementation in C (`lexer/lexer.c`, `lexer/lexer.h`).
- [x] Support for all planned keywords:
    - [x] `probe`, `if`, `elif`, `else`, `repeat`.
    - [x] `map`, `int`, `string` (Type declarations).
- [x] Literal parsing (Strings, Numbers).
- [x] Arithmetic and Comparison operators.
- [x] Error handling for illegal characters and malformed tokens.
- [x] Lexer verification via compiler test suite and example programs.

## Phase 2: Syntax Analysis (Parser)
Converting the token stream into an Abstract Syntax Tree (AST) that represents the program structure.

- [x] Design AST node structures (`parser/parser.h`):
    - [x] Probe definitions (`AST_PROBE`).
    - [x] Variable declarations and assignments (`AST_VAR_DECL`, `AST_ASSIGN`).
    - [x] Function/Helper calls (`AST_CALL`, e.g., `print`, `pid`, `uid`, `ktime`).
    - [x] Control flow (`AST_IF`, `AST_REPEAT`).
    - [x] Expressions (Arithmetic, Comparison).
- [x] Recursive Descent Parser implementation in C (`parser/parser.c`).
- [x] Parser error reporting with line number context.
- [ ] Parser error reporting with exact column information.
- [ ] AST visualization tools (e.g., Graphviz export / AST dump flag).

## Phase 3: Semantic Analysis & Type Safety
Validating the AST and ensuring verifier-safe semantics before code generation.

- [x] Symbol table management with scoped variable tracking (`semantic/symbol_table.c`).
- [x] Type checking (Expressions, assignments, comparisons).
- [x] eBPF Verifier pre-checks:
    - [x] eBPF 512-byte stack frame limit enforcement.
    - [x] Bounded repeat loops check.
    - [x] Helper function signature and argument count verification.
- [x] Direct AST lowering to verified instruction stream layout.

## Phase 4: eBPF Bytecode Generation
Directly emitting 64-bit eBPF instructions (`struct bpf_insn`) without LLVM/Clang dependencies.

- [x] Map EEL AST to 64-bit eBPF bytecode instructions (ALU, JMP, LD/ST, STX, CALL, EXIT).
- [x] Register Allocation for eBPF register set (`R0`–`R10`):
    - [x] Parameter passing (`R1`–`R5`).
    - [x] Scratch register allocation (`R1`–`R9`).
    - [x] Negative stack frame management (`R10 - 8` through `R10 - 512`).
- [x] eBPF Helper function call lowering:
    - [x] `bpf_trace_printk` (Helper 6) with runtime string literal synthesis on stack at `[R10 - 256]`.
    - [x] `bpf_ktime_get_ns` (Helper 5).
    - [x] `bpf_get_current_pid_tgid` (Helper 14) with 32-bit shift extraction.
    - [x] `bpf_get_current_uid_gid` (Helper 15).
- [x] Control flow jump backpatching:
    - [x] Conditional branches (`if`, `elif`, `else`) with relational jump opcodes (`BPF_JEQ`, `BPF_JGT`, `BPF_JGE`, `BPF_JLT`, `BPF_JLE`, `BPF_JNE`).
    - [x] Bounded `repeat` loops with unrolling/backward jump tracking.
- [x] Multi-Format Emission & Export:
    - [x] Raw bytecode binary export (`.bin`, `.raw`).
    - [x] C header export (`.h`) containing static byte array.
    - [x] 64-bit eBPF ELF relocatable object file generation (`.o` with `EM_BPF`, `.shstrtab`, `kprobe/<name>`, and `license` sections).
    - [x] Human-readable disassembly to stdout (opcode, registers, offset, imm).
- [ ] Map definitions and relocations (Hash maps, Array maps).

## Phase 5: Kernel Integration & Loader
Loading generated bytecode into the Linux kernel and attaching to trace points.

- [x] Minimal standalone `sys_bpf()` syscall wrapper in C (zero-libbpf dependency).
- [x] Standalone Kernel Loader utility (`loader/loader.c` -> `eel-loader`):
    - [x] Program loading via `BPF_PROG_LOAD` with automatic 64KB verifier log retrieval on failure.
    - [x] Kprobe attachment via tracefs (`/sys/kernel/tracing/kprobe_events`).
    - [x] Perf event allocation via `perf_event_open` and `PERF_EVENT_IOC_SET_BPF` binding.
    - [x] Real-time trace logger streaming from `/sys/kernel/tracing/trace_pipe`.
    - [x] Support loading from `.bin`/`.raw` files or direct stdin pipe.

## Phase 6: Tooling, CLI & Example Suite
Developer tooling, CLI flags, and reference test cases.

- [x] Multi-format compiler CLI: `./eel <source.eel> [-o <output>]`.
- [x] Build automation in `Makefile` (`make`, `make eel-loader`, `make clean`).
- [x] Comprehensive example programs suite (`examples/`):
    - [x] `01_hello_world.eel` (Basic kprobe & trace printk).
    - [x] `02_pid_filter.eel` (PID extraction & filtering).
    - [x] `03_if_else.eel` (Conditional branching).
    - [x] `04_elif_chain.eel` (Multi-branch conditional chain).
    - [x] `05_variables.eel` (Stack variable allocation & arithmetic).
    - [x] `06_ktime_latency.eel` (Nanosecond timestamp tracking).
    - [x] `07_uid_check.eel` (Root/user security auditing).
    - [x] `08_repeat_loop.eel` (Bounded iteration).
    - [x] `examples/README.md` documentation and compilation instructions.
- [ ] Unified `./eel run <source.eel>` one-step compile, load, and trace command.

## Phase 7: Expansion & Future Scope
Expanding language features, targets, and compiler optimizations.

- [ ] **Probe Targets:**
    - [ ] Tracepoints support (`/sys/kernel/tracing/events/...`).
    - [ ] `kretprobe` (kernel function return probes).
    - [ ] `uprobe` / `uretprobe` (user-space tracing).
    - [ ] XDP (eXpress Data Path) high-performance network packet filtering.
- [ ] **State & Communication (eBPF Maps):**
    - [ ] Hash map declaration (`map<string, int>`) and kernel map creation (`BPF_MAP_TYPE_HASH`).
    - [ ] Array map declaration (`BPF_MAP_TYPE_ARRAY`).
    - [ ] Map helper functions (`bpf_map_lookup_elem`, `bpf_map_update_elem`, `bpf_map_delete_elem`).
    - [ ] Ring buffer / Perf event array for high-throughput event streaming to userspace.
- [ ] **Optimizations & Diagnostics:**
    - [ ] Peephole optimizations (redundant register moves and dead stores).
    - [ ] Verifier-aware dead code elimination.
    - [ ] Benchmarking against Clang/LLVM (compile latency, binary size, verifier pass rate).
- [ ] **Ecosystem:**
    - [ ] Language Server Protocol (LSP) for editor autocompletion & syntax highlighting.
    - [ ] Packaging and single-binary release.
